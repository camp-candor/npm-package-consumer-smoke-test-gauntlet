# NPM Package Consumer Smoke Test  
Please test this remote npm package at this online npm location ---> {{FOCUS}}  as an **external consumer**. Do not modify or debug the package itself. The goal is to determine whether a normal user can install the published package from npm, import a public function, and execute it.  
After completing the test, create a report as a file using a zero padded slugified filename at the following location {{OUTPUT}} using the following format.  

## 1. Environment  
```
Package:
Installed package version:
Node version:
npm version:
Operating system:

```
Please get the actual installed version with:  
```
npm ls <package-name>

```
Also run:  
```
node --version
npm --version

```
## 2. Installation  
Paste the **exact command** used to install the package:  
```
npm install ...

```
Report:  
```
Install successful: YES / NO
Warnings:
Errors:

```
Do not use:  
* npm link  
* workspace:*  
* a local filesystem path  
* a local .tgz  
* a GitHub dependency  
* the original monorepo  
The package must come from the npm registry.  
## 3. Import Test  
Paste the **entire test file** you created.  
It should be minimal and import the function through the package’s public API, for example:  
```
import { someFunction } from "@scope/package-name";

console.log(someFunction(/* input */));

```
Do not import from internal paths such as:  
```
package/src/...
package/dist/...

```
unless that path is explicitly part of the package’s documented public API.  
Then report:  
```
Import successful: YES / NO

```
If NO, paste the complete error exactly as produced.  
## 4. Execution Test  
Run the test file and report:  
```
Function executed: YES / NO

Expected result:
Actual result:

```
Paste the complete terminal output, including warnings.  
## 5. Final Result  
Choose the **first stage that failed**:  
```
[ ] PASS — install + import + execution all succeeded
[ ] FAIL — npm installation
[ ] FAIL — module/package resolution
[ ] FAIL — public import/export
[ ] FAIL — function execution/runtime
[ ] FAIL — other

```
If it failed, include the complete unedited error.  
## Important  
Please **do not fix the failure before reporting it**.  
I specifically want to see the package as a normal npm consumer sees it. If something breaks, the original failure—including its stack trace and terminal output—is useful test data.  
A successful report should make it possible for someone else to reproduce the test using only:  
1. the package name and version,  
2. Node/npm versions,  
3. the install command,  
4. the test file, and  
5. the run command.
